# REQUIREMENTS · 文件日报

## 用户与场景
李，质量工程师（暖通/壁挂炉行业）。希望每天回看：这台电脑上各软件（微信、钉钉、QQ、浏览器下载等）都生成/保存了哪些文件，也能按日期和文件类型检索。

## 与用户确认的方向（2026-11-07）
1. **扫描范围**：常用目录自动监控（下载 / 文档 / 桌面），无需手动添加。
2. **软件归属**：两者都要 —— 既按“软件专属目录”推断归属（微信/QQ/钉钉/飞书/企业微信/WPS 内置规则 + 用户自定义），也支持按日期 + 文件类型查看。
3. **每日形式**：选日期看当天清单（前一天/后一天/日期选择器/近 14 天时间线 chips）。

## 功能需求
- R1 自动检测并监控常用目录；内置软件归属规则表，支持自定义监控目录与归属规则（设置面板增删）。
- R2 本地索引服务扫描监控目录：Windows `st_ctime`=创建时间判定“当日新建”，`st_mtime` 判定“当日修改”；构建按日期索引并持久化，应用重启不丢失；增量扫描带目录 mtime 水位剪枝，不全量重扫。
- R3 日期视图：翻日/跳选/时间线 chips；统计条显示当天文件数、总大小、分组数、索引总量与上次扫描时间。
- R4 当日清单：按软件 / 按类型两种分组切换；组内可折叠；文件名实时搜索过滤。
- R5 手动刷新（增量，带进度：已遍历目录/文件数、收录数）；设置中可全量重建。
- R6 文件行操作：在资源管理器中定位文件（仅允许监控范围内的路径）。
- R7 服务生命周期：数据目录单例锁、原子发布 connection.json、Bearer 鉴权 /health、UI 停止服务按钮 + 断开恢复指引。
- R8 状态覆盖：首次空态（引导首次扫描）、无文件日空态、加载态、服务未连接错误态、扫描超时告警。
- R9 视图偏好（tab/分组方式）用 sdk.data 持久化。
- R10 实时小结（2026-11-07 增补）：打开有文件的日期自动生成四栏面板——①哪些软件产生（按组大小排序+占比条）②内容构成（按类型聚合计数/字节）③存放位置评估（规则引擎：目录根部堆积、程序/数据类文件散落、临时缓存占比、大文件、来源分散度）④管理能力评估（0-100 整洁度打分 + 等级：井井有条/基本有序/需要整理/建议清理）。切换日期/新建修改页签即时重算，不请求网络。
- R11 AI 深度分析（按需）：小结面板“🤖 AI 深度分析”按钮把当天分组明细（组名/数量/大小/代表文件/扩展名分布，≤8 个样本/组）+ 规则观察交给宿主配置的聊天模型，输出“软件身份判断 / 内容性质 / 存放位置评估 / 管理能力与 3 条建议”。仅发送文件属性元数据，不发送文件内容；结果按 `日期+页签` 用 sdk.data 缓存，回看当天不重复消耗；调用前做 outputBudget/completionMetadata 握手，旧宿主明确拒绝并提示更新。

## 非功能与隐私
- 只读取文件的名称/大小/时间属性，不读取文件内容；仅扫描 settings 中的目录（默认用户自己的下载/文档/桌面）。
- 服务只监听 127.0.0.1，随机端口 + token 鉴权；数据（settings/index）存于应用数据目录，删除应用即清理。
- AI 分析为纯按需手动触发，默认浏览不产生任何模型请求；requiredCapabilities 为 data.kv + files.appData + ai.chat。

## 运行时依赖（显式声明）
- `runtime/python.exe`：随应用捆绑的官方 CPython 3.12.10 embeddable（win32，amd64），纯标准库实现后端；不要求用户系统安装 Python。
- macOS/Linux 未捆绑运行时：services 仅在 win32 可启动；跨平台分发需为对应平台补 runtime（记录为已知限制）。

## 已知限制
- 文件系统不记录“哪个软件生成了文件”，归属为目录前缀推断，非 100% 准确（内置规则 + 自定义规则缓解）。
- 移动进来的旧文件按其系统创建时间归入“过去日期”，不会出现在今天。
- 关闭应用窗口不会自动停止服务；停止需通过设置中的“停止服务”或重启宿主。
